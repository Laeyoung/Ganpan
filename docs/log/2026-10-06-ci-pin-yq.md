# Pin yq in CI and verify its SHA-256

- **Date:** 2026-10-06
- **Issue / PR:** — / (this PR)
- **Type:** ci
- **Version:** unchanged (1.16.0) — CI-only; nothing ships to installed users

## What changed
The Linux CI job downloaded `yq` from `releases/latest` with no integrity check. It now pins
`YQ_VERSION: v4.54.1` and verifies `YQ_SHA256` (taken from the release's `checksums` file and
cross-checked against a local hash of the binary) with `sha256sum -c` before installing,
mirroring the existing `SHELLCHECK_VERSION` pin.

## Why
Raised by the security pass of the PR #90 dev-review loop. A floating `latest` binary changes
CI's manifest/skill-YAML validator with no diff signal, and an unverified download is a
supply-chain gap — the same class #90 closed for the `npx` bootstrap by pinning a tag.

## Key decisions
- **Pin + checksum, not pin alone** — a tag can be re-pointed; the hash cannot.
- **No version bump** — CI is not part of any installed surface.

## Alternatives considered (not chosen)
- Installing yq via apt/snap — distro versions lag and differ from the macOS brew build.
- Also pinning the macOS `brew install` — Homebrew bottles are already checksummed; left as-is.
